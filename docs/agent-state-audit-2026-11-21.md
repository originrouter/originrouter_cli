# 原生控制与状态判断横向审计

本轮由 agy 的“终端控制信号被当成本地输入”问题扩展而来。范围包括原生 Claude/Codex 的 PTY 与终端设置控制、托管 Codex 的生命周期，以及 agy 的输入、问题、版本和就绪判断。默认启动分派、原生配置与网关模型归属没有改变。

## 按运行时的结论

| 运行时 | 与原问题的关系 | 本轮确认与处理 |
| --- | --- | --- |
| 原生 Claude Code | 没有 agy 的 `userTyping` 锁，不会以相同路径因终端回复永久拒绝消息 | 修复共享 PTY 延迟回车、effort 旧文本覆盖、设置并发与退出后的延迟按键；控制占用期间仍转交终端自动回复 |
| 原生 Codex | 没有上述输入锁；状态来自 rollout，不靠屏幕文字建立结构化审批 | 共享 PTY 的中断后回车和普通消息控制字符边界得到修复；没有新增 TUI 附着 app-server 或菜单控制 |
| Claude SDK | 通过结构化 SDK 控制，不读取原生终端输入框判断就绪 | 本轮检查与回归，未发现同一输入锁；没有改变 SDK、路由和模型行为 |
| Codex app-server | 不使用终端文字判断输入框，但通知和 RPC 响应可能交叉 | 修复快速任务已完成、启动响应才到达时重新锁成运行中；忽略其他线程及旧轮次的终结事件 |
| agy 原生 TUI | 正是本次输入状态问题的来源 | 继续修复弹窗输入、问题失败与冲突清理、最终空闲重绘、控制占用期间的终端回复、版本和问题面板旧文字误判 |
| 已有 agy ACP | 使用结构化会话和审批，不会经过原生键盘输入锁 | 保留原运行时，既有 ACP 协议回归继续覆盖；没有借此把 App 默认改回 ACP |

## 确认的问题与修复

1. **共享 PTY 延迟回车。** Claude/Codex 共用的提交函数在写入文本与 Enter 之间等待 30ms，中断或停止并不会使旧 Enter 失效。现在用输入代次和物理终端身份校验，停止、退出、中断或换终端后取消提交。
2. **Claude effort 旧文本覆盖。** 状态扫描保留 12KB 历史，旧“Set effort …”在新 badge 后仍可覆盖当前值。现在按最新观测的先后顺序取值。打开新 slider 时清空旧观测，slider 要求出现实际调整控件，旧确认句不再被当成打开成功。
3. **Claude 原生设置抢键盘。** 模式与 effort 原先各有自己的等待者，可以同时写进一个 TUI。现在共用操作占用；期间的普通远程聊天与本地键盘不插入设置流程，Ctrl+C 可取消。
4. **Claude 退出/取消后残留按键。** effort waiter 在 cleanup 时没有立即结束，异步流程还可能在延迟后写箭头或 `s`。现在立即清理等待者，并在每段异步操作后核对控制代次。
5. **终端自动回复被控制占用吞掉。** agy 原生作答或配置重启时原先丢弃所有 stdin，终端自动回复也会消失。现在仅转交完整、允许的焦点/设备/光标/颜色回复，保留跨分块解析；不把混在一起的用户文字转交。Claude 的原生设置占用使用同一机制。
6. **agy 弹窗按键遗留草稿锁。** 在原生权限、登录、信任或问题面板中输入的文字，不应被视为聊天草稿。现在区分输入所属的界面，实际聊天草稿保护保留。
7. **Ctrl+C 被不完整转义序列吞掉。** 解析器等待 CSI/OSC 后续字节时，中断字符也可能被当成序列的一部分，留下审批/问题状态。现在 Ctrl+C 先于序列状态处理并复位解析器。
8. **agy 问题工具失败后永久阻塞。** PostToolUse 的 error 或 transcript 的 ERROR 原先不会移除 question 条目。现在结束对应等待者和 App 交互，不再阻塞后续输入。
9. **原生已回答不同答案却保留旧问题。** 不匹配远程预期的最终答案不应被误报为成功，也不能永久保留问题。现在报告远程未确认并关闭旧控制。测试保留 Blue 与 Blueberry 不可混同的边界。
10. **最后一次空闲重绘丢失。** 远程问题操作占键盘时，原生最终空闲重绘可能先于结果 ACK 到达。操作结束后未重新判断 ready，会等一个未必存在的新重绘。现在释放输入占用后立即重新核对当前屏幕。
11. **对话提到版本号导致控件消失。** 原先在整屏任意位置查找 `Antigravity CLI x.y.z`，聊天内容也可触发兼容性关闭。现在仅在每个物理进程启动的 banner 阶段检查，启动进入编辑器后不再从对话内容推断版本。
12. **问题面板读到了旧示例。** 同一屏仍可留有旧 Question 示例。现在选择最后一个独立问题标题，仅解析该面板之后的选项，不混入前面的文字。
13. **Codex 已完成任务被迟到响应重新打开。** session 原先直接把 turn/start 返回的 id 设为当前轮，忽略了此前已到达的完成通知。现在保留有界终结记录、校验线程与轮次；旧响应不能复活已完成任务或覆盖当前新轮。通过真实 JSON-RPC 客户端的通知/响应交叉模拟验证。
14. **普通聊天与终端动作混用。** Claude/Codex 的 PTY 消息原先可将控制字符写成动作。现在普通聊天/命令文本与明确的 `terminal.input` 通道区分；普通 CRLF 归一为换行，显式原生按键保持可用。

此外检查了屏幕 dispose 是否会让 output flush 永久悬空：当前实现的测试通过，**没有把该猜测列为已确认 Bug**。

## 验证与实际边界

- `npm run test:state-audit`：24 项通过，包含本轮故障/状态序列与前一轮终端输入回归。关键新故障先用失败测试复现，再验证修复。
- `npm test` 与 `npm run test:agent-control` 全部通过；`npm run test:agy` 86 项通过。
- App 相关状态、交互、历史、原生模型与表单 36 项测试通过；未声称完整 App 套件通过。
- agy 真实后台原生链路：启动、消息、Hook 审批、设备 MCP、问题、文本上下文、模型/effort/模式重启、忙碌队列、停止和精确恢复。
- 真实外层终端启动 OriginRouter，再从 App 本地 API 发送：自动终端回复、真实草稿拒绝、清空后的恢复，三项通过。
- Claude 的 effort 与模式使用原生输出夹具和故障模拟；Codex 使用实际 JSON-RPC 客户端模拟乱序生命周期。本轮没有额外调用真实 Claude/Codex 账户执行任务。
- 本轮未把原生 Claude/Codex 任意本地草稿、任意版本原生菜单与 App 同时操作宣称为已验收。原生 Codex 仍没有结构化菜单/审批控制；不要把其 TUI 与 app-server 当成可互相附着。
- macOS ARM64 / agy 1.5.13 实测；Windows/Linux、实体手机公网 Relay、任意未来版本和所有复杂模态框仍不在本轮实测范围。

本轮修改需要由新启动的 CLI 进程加载。已经运行的用户进程不会因为磁盘源码更新而自动加载全部修复；没有为加载修复而终止或替换用户正在工作的会话。
